# MTG Hunter

Локальная программа для поиска карт Magic: The Gathering под русский рынок:
поиск по всей базе карт, импорт колод по ссылке, и — главное — подбор
недостающих карт у продавцов на **topdeck.ru** с готовыми черновиками
сообщений о покупке.

Работает целиком на вашей машине. Ничего не хостится, никуда не отправляется.

## Скачать и запустить

Нужен **Windows** и **Python 3.12 или новее** ([python.org](https://www.python.org/downloads/),
при установке отметьте «Add python.exe to PATH»). Места на диске — около 1.5 ГБ
под базы карт и комбо.

1. Скачайте архив: [**последний релиз**](https://github.com/Divenprim/MTG-hunter/releases/latest)
   → `Source code (zip)`. Или кнопкой `Code` → `Download ZIP` — это текущее
   состояние `main`.
2. Распакуйте в любую папку.
3. Запустите **`run.bat`**.

Первый запуск делает всё сам: создаёт окружение, ставит зависимости, скачивает
список сетов и собирает базу карт со Scryfall (~100 МБ, несколько минут).
Дальше открывается http://127.0.0.1:8765 в браузере.

Базу комбо (27 МБ) программа предложит скачать, когда откроете «Комбо в колоде»
в билдере — это одна кнопка и около минуты.

Обновиться до новой версии: скачайте архив заново и распакуйте поверх. Папку
`data` не трогайте — в ней ваши колоды, избранное и коллекция.

## Запуск

```
run.bat
```

При первом запуске сам создаст виртуальное окружение, поставит зависимости и
соберёт базу карт (несколько минут — качается ~100 МБ со Scryfall). Потом
откроет http://127.0.0.1:8765 в браузере.

Если загрузка оборвалась, следующий запуск распознает неполную базу и
пересоберёт её автоматически. Проверить базу вручную без запуска сервера:
`.venv/Scripts/python build_db.py --check`.

Пересобрать базу карт позже: `python build_db.py`.

### Вручную, без run.bat

```
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python fetch_sets.py     # список сетов для разбора строк продавцов
.venv/Scripts/python build_db.py       # база карт со Scryfall, несколько минут
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

Базу комбо (Commander Spellbook, 27 МБ) качает сама программа — кнопкой
«Комбо в колоде» в билдере, один раз.

Чистый клон запускается и без баз: страница открывается, а поиск честно
отвечает `Card database not built yet. Run: python build_db.py`.

### Про `samples/offers.json`

Снимок 1212 реальных объявлений с topdeck: на нём измерена точность разбора
строк продавцов — **89.6%** распознавания сета. Это публичные объявления с

## Что умеет

**Поиск карт** — 108 265 бумажных печатей локально. Два способа искать, но
**один язык запросов**: панель фильтров собирает тот же текстовый запрос и
показывает его, поэтому синтаксис видно, его можно править руками, и в коде нет
двух расходящихся реализаций поиска.

Панель фильтров: цвета кружками с режимами «включает / ровно / не больше»,
цветовая идентичность для Commander, **типы токенами** (вводите с подсказками
из 47 типов и 678 подтипов, добавляете сколько нужно, режим «все» или «любой
из»; плюс быстрые кнопки популярных типов), диапазон мана-стоимости, сила и
защита, редкость, формат, **подборщик сетов** (поиск по 988 сетам списком с
кодом, годом и числом карт; выбранные — токенами) и **группа «Исполнение»**
(без рамки, showcase, расширенный арт, во всю карту, без текста, etched,
серийная, galaxy/surge foil, промо). Плюс сортировка: по совпадению, имени,
мана-стоимости, новизне, редкости, цене.

**Secret Lair — одна кнопка.** Это не один сет, а пять (`sld` 2754 карты,
`slc`, `slp`, `slu`, `pssc`), а отдельные дропы внутри вообще не сеты: они
различаются только полями `promo_types` / `frame_effects` / `border_color`.
Поэтому `s:secretlair` разворачивается в группу, а исполнения фильтруются
отдельно: `s:secretlair is:borderless` даёт 1322 карты.

**Полное имя карты приоритетнее — и при точном совпадении, и при совпадении
по началу слова.** Ярусы: точное совпадение собственного имени карты → точное
совпадение имени стороны, флейвора или русского имени → начало собственного
имени → начало любого имени → алфавит. Поэтому `burg` находит `Burgeoning`
раньше, чем `Bilbo, Luckwearer // Burglar's Puzzle Box`.

**Точное совпадение по имени стоит первым в любой сортировке.** Запрос `tiamat`
показывает саму `Tiamat` выше однофамильцев (`Livaan, Cultist of Tiamat`,
`Tiamat's Fanatics`) даже при сортировке по возрастанию цены. Сортировка
упорядочивает всё остальное.

| Запрос | Значение |
|---|---|
| `t:creature,land` | тип; через запятую — «или» |
| `o:"draw a card"` | текст правил |
| `c:wu` / `c=wu` / `c<=wu` | включает / ровно / не больше |
| `id<=abzan` | цветовая идентичность; можно именем (`esper`, `jund`, `azorius`) |
| `cmc>=3`, `mv<5` | мана-стоимость |
| `r:rare,mythic` | редкость |
| `s:clb,m10` | сеты по коду |
| `f:modern`, `banned:legacy` | легальность |
| `pow>=4`, `tou<2` | сила / защита |
| `is:foil`, `is:etched`, `is:reprint` | исполнение |
| `is:secretlair` | вся группа Secret Lair |
| `is:borderless`, `is:showcase`, `is:extendedart` | особая печать |
| `is:serialized`, `is:galaxyfoil`, `is:promo` | промо-исполнения |
| `frame:etched`, `promo:prerelease`, `border:gold` | напрямую по полям |
| `cn>=2081 cn<=2101` | диапазон номеров — так задаётся дроп |
| `released:2025-07-14` | дата выхода печати |
| `otag:ramp`, `otag:theft-creature` | назначение карты; включает дочерние метки |
| просто слова | имя (рус/англ, **включая имена сторон**) или текст карты |

Русские имена есть у 21 758 печатей — «Удар Молнии» находится.

**Импорт колод** — по ссылке с Archidekt, Moxfield и mtgtop8, либо вставкой
текстом (формат Arena, `SB:`, секции `Sideboard` / `Commander`, в том числе
русские заголовки).

**Охота** — берёт колоду, вычитает вашу коллекцию, ищет остаток на topdeck и
собирает план покупки. Две стратегии:

- *меньше продавцов* — одна пересылка, один разговор;
- *минимальная цена* — дешевле, но продавцов больше.

На живом примере (4 Lightning Bolt + 2 Sol Ring, только рус, не хуже LP):
1040 ₽ у одного продавца против 628 ₽ у пяти. Разницу видно сразу.

**Избранное** — отложенные карты по папкам. Это список «хочу купить», в отличие
от коллекции: коллекция говорит, что у вас есть, и вычитается из колоды.
У каждой позиции своё нужное количество, заметка и, если надо, **конкретная
печать** (фойловый Secret Lair — это не то же желание, что дешёвый перепринт).
Карты переносятся между папками, папка целиком уходит в охоту, рядом видно
оценку в USD.

**Заказ в магазине** — магазину не пишут в личку, у него сайт и корзина.
Поэтому для магазинного лота вместо черновика письма готовится заказ:

- список карт для вставки («1 Burgeoning», по одной на строку);
- **прямая ссылка на карточку товара** у этого магазина — topdeck отдаёт их
  вместе с предложениями, и прямая ссылка лучше любого поиска;
- ссылка на поиск в магазине для тех карт, у которых прямой нет;
- кнопки «скопировать список» и «скопировать ссылки».

**Корзину собираете вы.** Программа готовит заказ и останавливается: наполнять
корзину запросами — это действие на коммерческом сайте от вашего имени, ровно
та черта, которую программа не переходит и с личными сообщениями. Плюс это
ломалось бы при любом редизайне магазина и делалось бы отдельно под каждый.

Ссылки в реестре (`app/shops.py`) — **только проверенные на живом сайте**:

| магазин | поиск ссылкой |
|---|---|
| SpellMarket | да, `route=product/search` |
| MTGSale | да, `/home/search-results?Name=` |
| Angry Bottle Gnome | нет — поиск работает только POST-формой |
| MTGTrade | нет — сайт не ответил при проверке |

Незнакомый магазин тоже работает: список и прямые ссылки на месте, просто
поиска нет. Придуманная ссылка, которая молча ищет пустоту, хуже отсутствия
ссылки — поэтому ничего не угадывается.

**Сообщения** — для каждого продавца-человека готовый текст: приветствие и список карт
**дословными строками из его ветки**, без счёта и итогов. Так это выглядит:

```
Добрый день!

По Вашей торговой теме интересуют:

1x Lightning Bolt (EN) (SP) (E01 #54) 150
1x Sol Ring (EN) (SP) (C18 #222) 80

Подскажите, всё в наличии?
```

Никакой арифметики: ни «1 шт. × 150 руб. = 150 руб.», ни «Итого». Продавец
узнаёт свою строку с первого взгляда, а количество и цена в ней уже есть.
Единственное, что добавляется, — «— нужно N шт.», и только когда вы берёте
меньше, чем в объявлении: из строки «11 Burgeoning» иначе не понять, что нужна
одна.

Черновик можно править прямо в окне — это ваше письмо. Правка сохраняется при
пересчёте плана, а вернуть сгенерированный текст можно кнопкой. Отправляете вы
сами, вручную: программа ничего не пишет от вашего имени.

**Заказано, но ещё не получено** — отдельное состояние между охотой и
коллекцией. Внизу каждого продавца повторяется сумма и есть кнопка «Отметить
заказанным». Карты остаются в охоте и колоде, но получают заметную отметку;
заказ с продавцом, составом и суммой сохраняется в `user.sqlite`. Когда карты
пришли, кнопка «Получено → в коллекцию» добавляет их к имеющимся. Отметку можно
снять, ничего не меняя ни в охоте, ни в коллекции.

### Докинуть карту в готовый заказ

«Вот эту ещё» — и вся польза в **порядке ответа**. Карта за 775 ₽ у того, у
кого вы уже покупаете, не стоит второй пересылки и второго разговора; за 270 ₽
у незнакомого — стоит. Поэтому под планом есть строка «Докинуть карту»:

1. вписываете имя (есть подсказки по базе);
2. программа делает **один** запрос к topdeck и показывает два раздела —
   сначала «**Есть у тех, у кого уже покупаем** — без второй пересылки», потом
   «**У остальных** — это ещё одна посылка и ещё один разговор»; в каждой строке
   цена, продавец, город и его дословное объявление;
3. **в заказ ничего не попадает, пока вы не выбрали.** Пока смотрите, план не
   двигается; «не надо» закрывает панель, не изменив ничего;
4. выбрали строку — карта уходит в лот этого продавца, помечается «выбрано
   вами» (пересчёт её не перенесёт), дописывается в список охоты и в строку
   «Берём» со своим количеством.

Сервер держит найденные предложения **в стороне** до подтверждения — просмотр
не меняет ни список карт, ни план. Это и проверяется тестом: до выбора карта
не появляется ни в плане, ни в списке.

### Кто поставщик — решаете вы

План предлагает, но решение за тем, кто платит. У каждой карты в плане видно,
у кого она берётся, и рядом — предложения, которые её обходят: «дешевле у того,
кто уже в плане» (без второй пересылки) и «дешевле вообще». Один клик — и
карта закреплена за выбранным продавцом, пометка «выбрано вами» и кнопка
сброса.

Полный список предложений открывается по кнопке: прокручиваемый список, где
у каждой строки цена, продавец, город и его дословное объявление — по нему и
видно, какую печать вы берёте. Список бывает длинным: у популярной карты вроде
Sol Ring это под двести предложений.

**«Купить всё у одного»** — выбор над планом со списком тех, кто может закрыть
заказ, и сколько карт из нужных каждый закрывает («4 из 4»). Что этот продавец
не держит, докупается где найдётся. Проход улучшения такой выбор не разбирает:
«беру всё здесь» — указание, а не предложение сэкономить.

Правка не теряет место: после пересчёта страница остаётся там, где была, и
открытый список предложений остаётся открытым.

### Проход улучшения

После любой стратегии идёт **проход улучшения**: каждая незакреплённая
позиция предлагается самому дешёвому предложению среди продавцов, которые уже
есть в плане. Достоверность при этом не размениваем — объявление с указанным
сетом и состоянием не вытесняется смутным дешёвым. Продавец, у которого не
осталось позиций, из плана выпадает, так что план становится и дешевле, и
короче. Сколько перенесено и сколько сэкономлено — написано в строке итога.

**Передумать можно в любой момент.** План — не приговор:

- «не это предложение» — карта нужна, но у другого продавца: в план встаёт
  следующее по очереди предложение;
- «не брать карту» — карта уходит из плана целиком;
- количество у каждой карты меняется полем в строке «Берём» — можно взять 1 из 4;
- всё перечисленное возвращается: рядом с каждым отказом есть «вернуть», а
  внизу — «вернуть всё как было», и план становится ровно таким, каким был.

Пересчёт мгновенный и **не делает ни одного нового запроса к topdeck**:
найденные предложения остаются в памяти сервера под номером поиска, и план
собирается заново из них. Отказы не накапливаются, а применяются заново при
каждом пересчёте — именно поэтому «вернуть» работает: отказ просто перестаёт
отправляться.

## Главная идея: строка продавца — это истина

На topdeck карты записаны свободным текстом, и каждый пишет по-своему:

```
1x Lightning Bolt (EN) (SP) (A25 #141) 160
3 Удар Молнии (М11) sp 130            <- кириллическая «М»
4 Lightning Bolt (NM EN CLB #187) - 145 руб
1 Lightning Bolt (JP) (PL, m11-149)
3 Удар Молнии (#146) [2 рус, 1 eng] - 130 руб.   <- смешанный лот
```

`app/lineparse.py` вытаскивает оттуда сет, номер, язык, состояние, фойл и
особую печать. На выборке из 1212 реальных объявлений сет определяется в
**89.6%** случаев. Из 126 промахов 84 — объявления, где продавец **вообще
ничего не указал**, так что практический потолок ~93%.

Поэтому три правила, на которых построен интерфейс:

1. **Исходная строка продавца всегда на виду**, а разбор — подписью рядом.
   Разбор может ошибаться, строка — нет.
2. **Ничего не выдумывается.** Не указан сет — так и написано «сет не указан».
   Промо вроде Judge Gift Cards выходили годами, поэтому помечаются как промо,
   а год не угадывается.
3. **Достоверность важнее цены.** Смешанный лот («разные», «2 рус, 1 eng») или
   объявление без описания не встанет в плане выше точно описанного, даже если
   дешевле. Иначе план заполнялся бы самыми мутными предложениями.

## Чему из выдачи topdeck нельзя верить

Два поля из выдачи topdeck использовать нельзя, и оба влияют на цену покупки.

**Имя карты (`eng_name`) — это ваш запрос, а не то, что продают.** Поиск на
topdeck ищет подстроку в строке продавца и подписывает каждый результат тем
именем, которое вы искали. По запросу `Burgeoning` приходит 69 объявлений, и
все подписаны «Burgeoning», хотя в строках:

```
Urban burgeoning 10
2 RTR Urban Burgeoning 10 руб.
2 <b>Blighted Burgeoning</b> (NM, March of the Machine)
1 March of Burgeoning Life (#201) [eng]  - 21
```

Это четыре разных карты, и дешёвые — все не те: настоящий `Burgeoning` стоит
порядка 2000 ₽.

**Цена (`cost`) тоже иногда прочитана неверно.** В строке
`1 Тиамат (Tiamat) #235/281 AFR RU 1300` topdeck принял номер коллекции за
цену и вернул 235 ₽ вместо 1300 ₽.

Поэтому решает только строка продавца:

- `app/offermatch.py` для каждой искомой карты собирает её собственные имена
  (включая русское, имена сторон и флейвор-имена) и **все чужие имена, которые
  содержат её имя как подстроку**. Если в строке есть более длинное чужое имя —
  объявление относится к той карте, и это видно: «в строке продавца другая
  карта: «Urban Burgeoning»». Если не видно ни одного имени — объявление не
  «подходит по умолчанию», а помечается как непонятное и в покупку не идёт.
- `price_in_line()` читает цену из строки сам и сравнивает с `cost`. При
  расхождении объявление помечается спорным: оно остаётся видимым с пояснением
  «topdeck считает 235 ₽, а в строке продавца 1300 ₽», но не может стать самым
  дешёвым предложением и не попадает в кеш цен.

В карточке видно и то, что скрыто: «Скрыто 45 предложений других карт» с
перечислением, каких именно.

## Двусторонние карты и совпадающие имена

Имя одной карты часто оказывается частью имени другой, а 3 185 карт вообще
имеют по две стороны. Поэтому имена живут в отдельном индексе `card_names`:
полное имя, имя **каждой стороны**, и русские формы — 59 914 записей.

Что из этого следует:

- поиск `Petty Theft` находит `Brazen Borrower // Petty Theft` и подписывает
  результат именем той стороны, которую вы искали, а не склеенным именем;
- в карточке есть кнопка «Перевернуть» — у `transform` и `modal_dfc` показываются
  обе стороны. У adventure/split-карт физически одна картинка, поэтому берётся
  общая: это ограничение данных Scryfall, а не недоделка;
- **карта важнее стороны.** `Lightning Bolt` — это и карта, и обратная сторона
  `Emeritus of Conflict // Lightning Bolt`; настоящая карта всегда выше;
- сопоставление объявлений с вашим списком идёт **строго по точному имени**
  (после нормализации регистра, пробелов и апострофов: `Tiamat’s` = `Tiamat's`).
  Объявление на `Tiamat's Fanatics` не может попасть в план как `Tiamat` — оно
  помечается «другая карта» и не покупается ни при каких фильтрах.

Это отвечает на реальную поломку: раньше сопоставление было подстрочным, и
соседняя карта могла оказаться в плане покупки под чужим именем.

## Откуда берутся цены

topdeck **сам агрегирует** русские магазины — в выдаче приходят
`angrybottlegnome`, `mtglavka`, `MagicSpark.shop`, `mymagic.ru`,

## Где лежат данные и как они не теряются

Всё пользовательское — избранное, коллекция, ожидающие заказы, колоды, версии,
кеш рублёвых цен —
лежит в **одном файле `data/user.sqlite`**. Отдельно от `cards.sqlite`, который
пересобирается и является лишь локальной копией Scryfall. Резервная копия
всего вашего — это копия одного файла.

Хранение устроено так, чтобы потерять данные было нечем.

**Снимок перед каждым изменением.** Добавили карту, переименовали папку,
удалили список, перезаписали коллекцию — предыдущее состояние сохраняется с
отметкой времени и причиной. Хранятся 40 последних. В интерфейсе есть панель
«Резервные копии» с кнопкой откатить, и сам откат тоже пишет снимок — вернуться
можно и назад.

**Тесты не видят ваших данных.** Переменная `MTGH_DATA_DIR` переводит
хранилище в другую папку, и юнит-тесты работают во временной.

**Перенос без потерь.** Старый `favourites.json` (и `collection.json`) при
первом запуске импортируется в базу и **переименовывается**, а не удаляется —
если импорт что-то понял неверно, оригинал лежит рядом как `.imported`.

Браузерная проверка `tests/ui_backups.py` проходит весь сценарий: создать
папку с картой, удалить её, вернуть из резервной копии.

## Билдер колод

Свои колоды с сохранением, редактированием и — то, ради чего он вообще нужен —
**ценой в рублях с topdeck**: по каждой карте и всей колодой. Ни Archidekt, ни
Moxfield этого для русского рынка не делают.

- добавление карт из подсказок в одно нажатие, количество плюсом-минусом,
  секции (мейн / сайд / командир / под вопросом), свои категории;
- **автораскладка по категориям** из тех же функциональных меток: рампа,
  туторы, удаление, контрмагия, добор, реанимация, защита, кража и контроль,
  жетоны, земли, существа. Категорию, которую вы вписали руками, автораскладка
  не перезаписывает;
- **проверка правил формата**, а это главное в билдере: цветовая идентичность
  командира, синглтон (с исключением базовых земель), лимит четырёх копий,
  размер колоды, легендарность командира, баны и «не входит в формат», опечатки
  в именах;
- статистика: кривая маны без земель, цвета, разбивка по типам, средняя МС;
- **версии колоды**: сохранить снимок, откатиться. Откат сам сохраняет текущее
  состояние отдельной версией — откат не должен быть тем действием, которое
  теряет работу;
- недостающее уходит в охоту или в список избранного одной кнопкой.

### Цены

Кешируются с отметкой времени и обновляются **только по кнопке**. Каждый запрос
к topdeck — это вежливые 1.5 секунды, то есть колода на 100 карт это около
двадцати секунд; делать это молча на каждое изменение недопустимо. Есть
отдельная кнопка «Только новые» — обновить лишь те карты, цены которых ещё
неизвестны.

По каждой карте видно **минимум, медиану и число предложений**: минимум это пол,
медиана — то, за сколько карта реально уходит. На живом примере: `Rhystic Study`
от 4 000 ₽ при медиане 7 258 ₽ по 62 предложениям.

### Голдфишинг

Две половины, потому что они отвечают на разные вопросы.

«Работает ли колода на ходах 1–4» — вопрос про перемешивание, и тысяча
смоделированных партий отвечает на него куда лучше, чем одна раздача руками.
Считается на сервере: доля играбельных рук (2–5 земель), распределение земель в
семёрке, к какому ходу выходит 3 и 4 земли, средняя МС в руке, есть ли что
разыграть на каждом ходу.

«Как выглядит рука» — тут нужна настоящая рука: раздать, взять карту, муллиган.

**Допущения расчёта напечатаны под цифрами.** Одна земля за ход; рампа, фетчи и
кантрипы не моделируются (с ними в реальности будет лучше); муллиганы не
моделируются. Симуляция, которая прячет свои допущения, хуже, чем её отсутствие.

## Поиск по назначению, а не по формулировке

«Рампа», «кража существ», «смена контроля» — это не фразы, напечатанные на
картах, поэтому текстовым поиском они не находятся в принципе. Взяты
**функциональные метки Scryfall Tagger**: 4524 метки, 231 020 привязок,
курируемые сообществом — это заведомо лучше, чем угадывать смысл регексами по
тексту правил.

В панели фильтров есть готовые темы по-русски (рампа, туторы, точечное
удаление, масс-удаление, кража существ, смена контроля, реанимация, мельница,
сакр-аутлет, сокровища и ещё десяток) и поиск по всем 4524 меткам с описаниями
и числом карт.

**Метки иерархичны, и это учитывается.** У `control-changing-effects` своих карт
ноль — они висят на дочерних метках, поэтому запрос по родителю раскрывается в
23 метки и даёт 806 карт. Две выбранные темы складываются через И, значения
через запятую — через ИЛИ.

Руками: `otag:ramp`, `otag:theft-creature`, `otag:sweeper cmc<=4 id<=abzan`.
Неизвестная метка возвращает **ноль**, а не всю базу — иначе сломанный фильтр
выглядел бы как работающий.


### Кеширование статики

`/`, `/static/*.js` и `/static/*.css` отдаются с `Cache-Control: no-cache,
must-revalidate`, поэтому перезагрузка всегда запускает текущий код, а Ctrl+F5
не нужен. ETag на месте, так что перепроверка — дешёвый 304. На ответы `/api/*`
это не распространяется: у них своя семантика.

## Работа с загруженной колодой

Импорт — это только первый шаг; дальше надо решить, что покупать. Поэтому в
каждой строке колоды стоят те два факта, которые это решение и определяют:
**сколько копий не хватает** и **сколько стоит одна**.

- сверху сводка: `нет в коллекции: 9 назв. / 19 шт. ≈ $157.24`, и отдельная
  плитка «Нужно докупить» в статистике;
- фильтр по имени внутри колоды, отбор «только которых не хватает / только те,
  что есть / не распознанные», сортировка по цене, мана-стоимости, имени или
  размеру нехватки;
- быстрый выбор: **всё, только нехватку, дороже $5, редкие и мифики,
  инвертировать**. Работают по тому, что сейчас видно, поэтому фильтр и быстрый
  выбор складываются, а не спорят;
- панель выбора считает `выбрано 9 назв. · 19 шт. ≈ $157.24` и не уезжает при
  прокрутке;
- выбранное уходит **в существующий список или в новый** (создаётся на ходу,
  одним запросом) либо сразу **в охоту**;
- клик по строке — выбрать, **Shift+клик — диапазон** (в том порядке, в котором
  строки видны, то есть с учётом сортировки и фильтра), клик по картинке — открыть карту.

Количество берётся то, которого **не хватает**, а не как в колоде: список
избранного — это список покупок. Если карта есть полностью, берётся её
количество из колоды.

## Как найти карты одного дропа Secret Lair (например, по Сонику)

Коротко: вкладка **Поиск карт → Фильтры → «Дропы Secret Lair»**, вписать
`sonic` и щёлкнуть найденный дроп. Получите весь дроп — 21 карту, включая те,
у которых в названии Соника нет.

Почему для этого нужен отдельный механизм, а не просто поиск по слову:

- `sld` — это **один сет на 2754 карты** из сотен разных продуктов, и **у
  Scryfall нет поля с названием дропа вообще**;
- поиск по слову «sonic» даёт неверный ответ в обе стороны: он **пропускает**
  `Amy Rose`, `Knuckles the Echidna`, `Dr. Eggman`, `Miles "Tails" Prower` —
  слова «sonic» в их именах нет; и **добавляет лишнее** — `Sonic Screwdriver`
  из Doctor Who;
- дроп опознаётся по **непрерывному участку коллекционных номеров** внутри сета
  и даты. Sonic-дроп — это `sld #2081-2101` от 2025-07-14. Одной даты
  недостаточно: в тот же день вышел ещё дроп Lotus Petal (`#7030-7037`).

Это эвристика, и в интерфейсе она честно описана составом дропа, а не
выдуманным названием: у каждой строки видно дату, диапазон номеров, число карт
и перечень содержимого, где совпавшие карты подсвечены.

Руками то же самое: `s:sld cn>=2081 cn<=2101`.

### Флейвор-имена

В Secret Lair перепринты печатают под тематическим именем: `Hammer of Nazahn`
на карте написан как **«Piko Piko Hammer»**, `Lightning Bolt` — как
«Vivi's Thunder Magic». Такие имена есть у 629 печатей, и они теперь
ищутся — причём выдаётся именно та печать, на которой имя напечатано.

Это важно дважды: так написано на карте, которую вы держите в руках, и **так
пишут продавцы на topdeck** — без этого их объявления невозможно было
сопоставить с картой.

## Про картинки продавцов

Просьба «показывать картинки, которые вставляют продавцы» упирается в факт:
**на topdeck таких картинок нет.** Проверено на данных, а не предположено:

- в выдаче поиска нет ни поля с изображением, ни тега `<img>` — в `line`
  встречается только `<b>`;
- в теме продавца все 28 картинок оказались интерфейсом сайта (логотип, значки,
  реклама, аватар), а маркеры вложений IPS (`ipsAttachLink`, `data-fileid`,
  `ipsAttachment`) — ровно нули;
- где фото всё-таки есть, продавцы дают **внешние ссылки**: Telegram, Яндекс.Диск.
  Таких строк 5 из 1212.

Поэтому вместо несуществующих фото сделано то, что отвечает на исходный вопрос
«какая это версия»:

1. **ссылки продавца вытаскиваются** из текста объявления и показываются
   отдельной пометкой «фото продавца»;
2. рядом стоит **картинка распознанной печати** с подписью
   «на картинке: MH2 · Modern Horizons 2 #138», а если сет продавцом не указан —
   так и написано, что версия предположительная;
3. в окне карты есть таблица всех печатей: клик меняет картинку, и эту же
   печать можно закрепить в избранном.

## Комбо

Комбо придумывают люди, и всё придуманное собрано в **Commander Spellbook** —
там 108 тысяч комбо: какие карты, в каком порядке и что получается. Программа
скачивает их одним файлом и держит локально.

Два вопроса, и второй важнее:

1. **какие комбо в колоде уже собраны** — кнопка «Комбо в колоде» в билдере;
2. **до каких не хватает одной карты**. Это и есть список покупок: у
   недостающей карты видна цена в рублях (если известна) и кнопка «в охоту».
   Отдельная кнопка отправляет в охоту все недостающие карты сразу.

На живой колоде из 60 карт: **1 комбо собрано и 16 таких, где не хватает одной
карты** — это ровно та подсказка, которую иначе не получить.

У каждого комбо показано, что оно даёт («Infinite colorless mana», «Win the
game»), сколько колод с ним на Spellbook, нужная мана, условия и пошаговое
объяснение. Карты-«шаблоны» («любой перманент за {C}») помечены пунктиром и
недостающими не считаются: их нельзя купить, под них подходит что угодно
подходящее.

В окне карты есть «Комбо с этой картой» — у Thassa's Oracle их 40. Там
намеренно **не** написано «собрано»: колоды, с которой сверять, в этом окне нет,
и утверждать было бы нечестно; вместо этого сказано, из скольких карт комбо.

### Как отфильтрован машинный мусор

Spellbook **генерирует** варианты механически: 108 779 записей — это
**27 345 базовых комбо**, и у одного базового бывает до 858 вариантов, которые
отличаются только тем, какая карта закрывает взаимозаменяемое место. Плюс
46 286 записей не стоят ни в одной колоде. Поэтому:

- **варианты одного базового комбо схлопываются в одну строку.** Phyrexian
  Metamorph копирует существо и подставляется в десятки вариантов; вместо
  десяти строк «купи Felidar Guardian / Kiki-Jiki / Wispweaver Angel» — одна:
  «достроит любая одна из N», карты отсортированы по цене в рублях;
- **шаблон считается требованием.** «Любой перманент, кастуемый за {C}» нельзя
  купить и нельзя проверить по списку карт, поэтому он назван отдельно: комбо
  с невыполненным шаблоном не попадает в «собрано», а помечается «карты есть,
  нужно условие», в нехватке пишется «не хватает 1 + условие»;
- **непопулярные скрыты по умолчанию.** Показываются комбо, которые стоят хотя
  бы в одной колоде; галочка «показывать и те, что никто не играет» включает
  остальное. В шапке написано, что показано.

Фильтр по статусу (`status = 'OK'`) на сегодняшних данных не отсеивает ничего —
у всех записей статус OK — и оставлен на случай, если Spellbook начнёт отдавать
брак.

### Откуда и сколько это стоит

`json.commanderspellbook.com/variants.json.gz` — 27 МБ в архиве, 600 МБ JSON
внутри. Файл разбирается **потоком** (`app/combos.py`) в компактную
`data/combos.sqlite` (132 МБ): из каждого комбо берутся карты, шаблоны,
результат, шаги, условия и легальность, а картинки, тексты и цены
выбрасываются — они уже есть локально. Сборка: **45 секунд**, скачивается по
кнопке и только один раз.

Почему локально, а не запросами к сайту: вопрос «каких комбо мне не хватает
одной карты» — это соединение сотни имён со всеми комбо разом. По сети это
сотни запросов, локально — один SQL и 0.02 с.

Разбор идёт по индексу в буфере, без нарезки строк: один блок разворачивается
в 23 МБ текста, и копирование буфера на каждом объекте сделало бы разбор
квадратичным. На это есть тест, который скармливает документ по 7 байт.

## Предложка карт по командиру

Выбрали командира — программа показывает, что в такие колоды кладут другие.
Кнопка «Предложка по командиру» в билдере; если в колоде назначен командир, он
подставляется сам, иначе можно вписать любого (в том числе по-русски —
«Тиамат» найдётся).

Данные берутся с **EDHREC**, который публикует страницы командиров готовым JSON
(`json.edhrec.com/pages/commanders/<slug>.json`) — ничего парсить не нужно, один
запрос на командира. По каждой карте оттуда приходит:

- в скольких колодах этого командира она стоит и сколько таких колод всего —
  это и есть главное число, «в 79% колод»;
- **синергия** — насколько чаще она встречается здесь, чем в колодах вообще.
  Именно она отделяет карты, которые берут *из-за командира*, от просто хороших:
  Sol Ring стоит везде, Dragon Tempest — нет.

Дальше начинается то, чего на EDHREC нет: каждая строка соединяется с вашими
данными — **есть ли карта у вас** (коллекция), **стоит ли уже в колоде**, и
**сколько стоит в рублях** (из кеша цен topdeck). Отсюда же одним нажатием: «в
колоду», «в охоту», или отметить несколько и добавить пачкой.

Рублёвых цен поначалу почти нет — они появляются только там, где topdeck уже
спрашивали. Поэтому есть кнопка **«Узнать цены на отмеченные»**: отмечаете
несколько карт и получаете их цены (1.5 с на карту, не больше 40 за раз).
Само открытие предложки к topdeck **не обращается вообще** — 250 карт по 1.5 с
это минуты трафика.

Фильтры: скрыть то, что уже в колоде; только чего нет у вас; не реже, чем в
10 / 25 / 50% колод. Порядок: как на EDHREC, по доле колод, по синергии,
дешевле в рублях или в долларах (карты без известной цены уходят в конец, а не
притворяются бесплатными).

Страница командира кладётся в кеш на диск (`data/edhrec/`) на две недели —
статистика за неделю меняется на доли процента. Повторное открытие — 150 мс
вместо запроса. Кнопка «Обновить данные» запрашивает заново. Если EDHREC не
отвечает, показываются прошлые данные с честной пометкой, а не пустой экран.

## Как смотреть результаты поиска

- **Предпросмотр по наведению.** Задержали курсор на карте — рядом появляется
  её большая версия. У двусторонних карт видны сразу обе стороны. Окно
  переворачивается у края экрана, не залезает на строку поиска и не
  перехватывает мышь, так что клик всегда достаётся плитке. Уходит по уводу
  курсора, прокрутке, клику и `Esc`.
  Работает не только в поиске: строки таблицы печатей, карты в колоде и в
  билдере, миниатюры в плане покупки — везде, где уже была картинка.
- **Три плотности сетки** (кнопки справа от сортировки; выбор запоминается):

  | режим | плитка | видно целиком на 1280x800 |
  |---|---|---|
  | плотно | 107 px | **33 карты** |
  | средне (по умолчанию) | 147 px | **16 карт** |
  | крупно | 239 px | 5 карт |

  В плотном режиме под картинкой остаётся только имя — остальное читается в
  предпросмотре.
- **Строка поиска закреплена**: новый запрос не требует прокрутки наверх.
  Счётчик «показано N из M» стоит в той же строке, а таблица синтаксиса — внутри
  панели фильтров, которая этот синтаксис и собирает.
- **Быстрые действия на плитке.** При наведении в углу карточки появляются
  «+ охота» и «★»: добавить карту, не открывая её. Обычный клик по-прежнему
  открывает карту.
- **Клавиатура.** `/` — в поле запроса, `↓` — из поля в результаты, стрелки —
  по картам (`↓`/`↑` на строку, не на карту), `Home`/`End` — к первой и
  последней, `Enter` — открыть, `Esc` — назад к запросу. Под курсором сама
  собой показывается большая карта, так что перебирать выдачу можно не касаясь
  мыши.

  Предпросмотр появляется сразу: первым кадром идёт миниатюра, которая уже есть
  на плитке, и подменяется на полную по загрузке — на холодном кеше Scryfall
  отдаёт полную картинку 4–6 секунд.

## Как показывать колоду

Пять видов, переключатель в строке над списком:

| вид | что показывает |
|---|---|
| **стопками** (по умолчанию) | колонка на группу, карты в стопке — видна шапка каждой |
| **картинками** | все картинки целиком, группы переносятся по ширине экрана |
| **таблицей** | строки с количеством, категорией, ценой в рублях и в долларах |
| **компактно** | те же строки без картинок и категорий |
| **текстом** | строки «количество имя» — формат, который понимают все сайты и магазины |

Рядом — группировка (тип карт, категории, мана-стоимость, цвет, цена,
редкость, ключевое слово), сортировка внутри группы и размер карт в три
положения.

### Раскладка колонок

В стопочном виде с группировкой **по категориям** колонки раскладываются
вручную: кнопка «Колонки…» открывает панель, где плитки категорий
перетаскиваются между колонками. Колонка может держать несколько категорий,
колонки добавляются кнопкой и убираются крестиком — категории при этом не
теряются, а переезжают в первую. «По одной на колонку» возвращает исходное.

Раскладка хранится в браузере для каждой колоды отдельно. Новая категория,
которой в раскладке ещё нет, добавляется в последнюю колонку, а не исчезает.

Карты тоже перетаскиваются — из стопки в стопку, и это меняет их категорию.
Работает только при группировке по категориям: при группировке по типу или
цвету колонки считаются из самих карт, и бросок в колонку ничего не значил бы.
В заголовке колонки — количество и сумма в рублях; у карты, которой не хватает,
оранжевая обводка, а если цена известна — ярлык с ценой. В конце есть колонка
«+ новая категория»: бросаете туда карту, вводите название, категория
создаётся.

### Геометрия стопки

Видна только шапка карты — имя, стоимость и цена в рублях:

| режим | карта | полоса | 24 карты → высота колонки |
|---|---|---|---|
| плотно | 134 px | 24 px (13%) | 576 px |
| средне | 182 px | 30 px (12%) | 720 px |
| крупно | 232 px | 36 px (11%) | 864 px |

Считается это точно: карта высотой 139.4% своей ширины (680/488), карточка в
стопке занимает ровно полосу, картинка выступает вверх поверх лежащих выше, а
под стопкой оставлен запас под картинку последней карты. Высота колонки выходит
ровно `(n-1) × полоса + карта` — на это есть проверка, как и на то, что полоса
не меньше 22 px, иначе в неё не попасть курсором.


При наведении карта поднимается над стопкой, а рядом открывается её большая
версия — тот же предпросмотр, что и в поиске.

## Плотность в билдере

То же самое для колоды — кнопки рядом с выбором вида:

| режим | строка | видно из 60 |
|---|---|---|
| плотно | 34 px | **26** |
| средне | 54 px | 17 |
| крупно | 77 px | 11 |

Плотность действует и на вид «картинками» (плитка 92 / 130 / 186 px), и
запоминается отдельно от плотности поиска.

Рядом — выключатель **«Статистика»**: блок статистики занимает 250 px над
списком карт, и в свёрнутом виде список начинается на 270 px выше. Выбор
запоминается.

## Мелочи, которые экономят время

- живой поиск с задержкой 400 мс — Enter не нужен;
- `/` — прыгнуть в поиск, `Esc` — закрыть карточку;
- клик по карте открывает окно: большая картинка, текст, легальность,
  **все печати** с ценами (клик по печати меняет картинку) и кнопка
  «Цены на topdeck» — проверить одну карту, не собирая колоду;
- «В охоту» с количеством 1/2/3/4; если карта уже в списке, количество
  складывается, а не дублируется строкой;
- состояние сохраняется в браузере: запрос, сортировка, фильтры, список охоты,
  фильтры охоты, активная вкладка. Перезагрузка не теряет работу;
- «Показать ещё» и счётчик «показано N из M»;
- статистика колоды: кривая маны без земель, разбивка по цветам, средняя
  мана-стоимость, оценка в USD, список форматов, где колода легальна;
- «Перенести в охоту» из колоды и «Скопировать колоду» списком;
- «Скопировать все сообщения» и «Выгрузить план текстом» — в выгрузке рядом с
  каждой позицией стоит дословная строка продавца;
- коллекция загружается из файла, не только вставкой;
- во время охоты видно, сколько секунд уже идёт запрос.


## Быстродействие

Поиск отвечает за 0.24–0.48 с, справочник сетов — мгновенно из кеша. Было
1.3–1.6 с, и это стоит помнить при доработках, потому что причины неочевидные:

- **WAL разрастался до 147 МБ** после сборки и миграций. Каждое новое
  соединение обязано построить снимок WAL — плюс секунда к каждому запросу.
  `checkpoint()` сворачивает WAL и обновляет статистику; он вызывается в конце
  сборки, и его же надо звать после любых миграций.
- **Кеш страниц SQLite — на соединение,** а соединения у нас потоко-локальные.
  Без `PRAGMA mmap_size` каждый новый поток читал страницы заново. mmap идёт
  через кеш ОС и разделяется между соединениями.
- `/api/sets` и `/api/types` кешируются в процессе: это GROUP BY по 108k строк,
  а страница просит их при каждой загрузке.
- `total` считается только для первой страницы — это отдельный полный проход.

### Как читается выдача topdeck

Публичного API у topdeck нет, но страница поиска отдаёт результаты **готовым
JSON**, вшитым в бутстрап Knockout-вьюмодели `SinglesSearchVM`. Мы поднимаем
этот JSON, а не парсим HTML-таблицу (её всё равно строит JS). Поэтому чтение
устойчивое, а не хрупкое.

Поиск работает **без авторизации**. Запросы идут по одному с паузой 1.5 с:
`robots.txt` для `User-Agent: *` закрывает только `/calendar/`, но грузить
чужой сайт всё равно не стоит.

## Чего пока нет

- **Склады продавцов через вашу сессию.** `TopdeckClient` умеет принимать
  cookies, но страницы «все карты продавца» не разбираются и поля для входа в
  интерфейсе нет. Это следующий логичный шаг: он позволит доукомплектовать
  заказ у уже выбранного продавца.
- **Moxfield может отказать.** Их API за Cloudflare и пускает только
  одобренные клиенты. Программа честно скажет об этом и предложит вставить
  список текстом (Export → Text).
- **mtgtrade.net не подключён.** У сайта просроченный TLS-сертификат, и
  topdeck уже покрывает магазины, так что смысла в парсере под него мало.
- **Промо и редкие печати.** Judge Gift Cards, Player Rewards, From the Vault,
  MagicFest — определяются как семейство, но не до конкретного сета.
- Автоотправка сообщений не делается сознательно: черновик готовит программа,
  отправляете вы.
