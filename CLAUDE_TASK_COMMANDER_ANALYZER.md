# Задача: автоматический анализ Commander-колоды

Нужно добавить в MTG Hunter модуль автоматического анализа Commander-колод.

Цель: по существующей колоде в MTG Hunter определять и показывать:

- ориентировочный Commander Bracket: B1 / B2 / B3 / B4 / B5;
- Power Score 0–100;
- Salt Score 0–100;
- основные причины, почему колода получила именно такой результат.

Важно: Bracket, Power и Salt — это разные показатели и не должны сводиться к одной общей формуле.

Анализ должен по возможности использовать уже существующие данные и модули проекта, включая текущую базу карт, теги, Commander Spellbook, анализ комбо, win conditions, deck shape, goldfish и существующую модель колоды.

Нужно учитывать как минимум:

- Game Changers;
- количество и качество туторов;
- fast mana;
- interaction;
- free interaction;
- combo и infinite combo;
- размер combo-пакетов;
- участие командира в combo;
- стабильность сборки combo;
- скорость игрового плана;
- card advantage;
- recursion / resilience;
- stax;
- resource denial;
- mass land destruction;
- extra turns;
- hard locks;
- commander dependency.

Отдельно нужно различать:

- сильную, но нормальную для игры колоду;
- более слабую, но крайне “солёную” колоду;
- high-power casual;
- optimized;
- cEDH.

Не определять Bracket простой разбивкой Power Score по диапазонам.

Результат должен быть объяснимым. Пользователь должен видеть не только число, но и что именно двигает деку вверх или вниз.

Желаемый результат для UI примерно такой:

```
B3 — Upgraded
Confidence: 87%

Power: 78/100
Salt: 42/100

Speed:           74
Consistency:     86
Interaction:     71
Fast Mana:       63
Tutors:          88
Combo:           91
Stax:             7
Resource Denial:  4
```

И ниже:

```
Почему B3:
- высокая плотность туторов;
- двухкарточная combo;
- одна combo piece находится в command zone;
- хороший interaction package;
- недостаточно fast mana / free interaction для уверенного B4.
```

Также желательно показывать карты, которые сильнее всего повлияли на Power / Salt / Bracket.

Официальные Commander Brackets и Game Changers меняются, поэтому правила желательно сделать обновляемыми, а не зашивать навсегда в код.

Нужно добавить тесты и не ломать существующие функции MTG Hunter.

Сначала изучи текущий код и используй существующую архитектуру проекта вместо создания параллельной системы.

После реализации не считать задачу завершённой без проверки на нескольких реальных Commander decklists разных уровней силы.
